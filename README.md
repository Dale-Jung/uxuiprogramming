# Honeymoon Travel — 신혼여행 준비 계획 설정\

## 제출란 (26.10.23부 추가)
1. GitHub Repository URL: https://github.com/Dale-Jung/uxuiprogramming
2. Published Website URL: https://dale-jung.github.io/uxuiprogramming/

## 사용자와 목표
- 사용자: 다카마쓰 신혼여행을 준비하는 예비부부
- 목표: 여행 제목과 준비 조건을 설정하고, 완료한 계획을 보관해 다시 확인한다.
- 핵심 행동: 여행 준비 동의 → 정보 입력 → 조건 선택 → 내용 확인 → 설정 완료 → 목록 저장 → 다시 열기 또는 삭제

## 사용자의 흐름
1. 여행 준비를 위한 정보 수집에 동의하고 '여행준비 설정하기'를 누른다.
2. 안내 팝업을 확인하고 '동의하고 설정 시작하기'를 누른다.
3. 여행 제목을 입력한다. 비어 있으면 같은 단계에서 안내를 받는다.
4. 준비 시간을 선택하고 필요하면 여행 질문을 포함한다.
5. 제목, 준비 시간, 여행 질문 설정을 확인하고 수정하거나 완료한다.
6. 설정 완료 안내를 확인하고 필요하면 다시 설정한다.
7. 완료 화면에서 계획을 저장하고 목록에서 다시 열거나 삭제한다. (26.10.23부 추가)

## 인터랙션 시나리오

### 1. 시작과 여행 준비 안내
- 행동, 이벤트: 정보 수집 동의 체크박스를 선택하고 '여행준비 설정하기'를 클릭한다.
- 조건: 여행 준비를 위한 정보 수집에 동의했는가?
- 반응, 다음 상태: 동의 전에는 시작 버튼을 누를 수 없다. 동의하면 버튼이 활성화되고 준비 가능 안내가 표시된다. 버튼을 누르면 안내 팝업이 열린다.
- 팝업에서 '돌아가기'를 누르거나 Esc를 누르면 팝업을 닫고 동의를 해제한 뒤 시작 화면에 남는다.
- '동의하고 설정 시작하기'를 누르면 여행 제목 입력 화면을 연다.

### 2. 여행 제목 입력
- 행동, 이벤트: 여행 제목을 적고 '준비 조건 선택하기'를 클릭한다.
- 조건: 앞뒤 공백을 제외한 제목이 비어 있는가?
- 반응, 다음 상태: 비어 있으면 같은 화면에 오류를 표시하고 제목 입력창으로 초점을 옮긴다. 제목이 있으면 저장하고 준비 조건 선택 화면으로 이동한다.
- 입력 예시: '다카마쓰 신혼여행'

### 3. 준비 조건 선택
- 행동, 이벤트: 준비 시간을 바꾸고 여행 질문 포함 여부와 질문 수를 선택한 뒤 '내용확인하기'를 클릭한다.
- 조건: 여행 질문을 포함하도록 선택했는가?
- 반응, 다음 상태: 준비 시간은 3분, 5분, 10분 중 선택하며 현재 값을 표시한다. 여행 질문을 선택했을 때만 질문 수 선택 영역을 보여 준다. 질문 수는 1개, 2개, 3개 중 선택한다.
- '이전'을 누르면 입력한 제목을 유지한 채 제목 입력 화면으로 돌아간다.
- '내용확인하기'를 누르면 현재 조건을 저장하고 내용 확인 화면으로 이동한다.
- 준비 시간은 여행 기간이 아니라 여행 계획을 준비하는 시간이다.

### 4. 내용 확인과 수정
- 행동, 이벤트: 여행 제목, 준비 시간, 여행 질문 설정을 확인하고 '수정하기' 또는 '설정 완료하기'를 클릭한다.
- 조건: 입력한 내용을 수정할 것인가, 완료할 것인가?
- 반응, 다음 상태: 제목과 준비 시간을 요약해 보여 준다. 여행 질문을 선택했다면 질문 수와 '개 포함'을 표시하고 선택하지 않았다면 '미포함'을 표시한다.
- '수정하기'를 누르면 선택한 값을 유지한 채 준비 조건 화면으로 돌아간다. 제목도 바꾸려면 그 화면의 '이전'을 누른다.
- '설정 완료하기'를 누르면 완료 안내 화면으로 이동한다.

### 5. 완료와 다시 설정
- 행동, 이벤트: 설정 완료 안내를 확인하고 필요하면 '다시 설정하기'를 클릭한다.
- 조건: 새로운 여행 준비 계획을 입력할 것인가?
- 반응, 다음 상태: 완료 화면을 보여 준다. 다시 설정하면 제목과 요약을 비우고 준비 시간은 5분, 여행 질문은 미선택, 질문 수는 2개로 초기화한 뒤 제목 입력 화면으로 돌아간다.

## 그 밖의 화면 동작
- 여행 계획 탭: 탭을 클릭하면 선택한 설명만 보여 준다.
- 화면 테마: 버튼을 누르면 밝은 테마와 어두운 테마가 바뀐다.
- 여행자 이름: 입력한 글자 수를 최대 10자 기준으로 표시한다.
- 이메일 신청: 빈 값과 이메일 형식을 확인한 뒤 완료 문구를 표시하고 신청 버튼을 비활성화한다.

## 반응형 화면
- 콘텐츠는 화면 너비에 맞춰 줄어들며 최대 너비는 1100px이다.
- 768px 이하에서는 메뉴, 여행 계획 탭, 이메일 폼을 세로로 배치한다.
- 확인할 화면 너비: 1100px / 769px / 768px / 390px

## 실행 방법과 구현 범위
- index.html, style.css, script.js를 같은 폴더에 두고 assets 폴더도 함께 둔다.
- index.html을 브라우저에서 열어 확인한다.
- 9주차 수정본의 화면 동작을 기준으로 작성했다.
- 안내 팝업은 여행 준비 설정과 저장 경로를 소개한다. 실제 녹음 기능은 없다. 여행 질문은 포함 여부와 질문 수만 설정하며 자동 생성하지 않는다.
- 이메일 신청은 화면 시연용이며 실제 이메일 발송이나 서버 저장은 하지 않는다.
- 새로고침하면 입력값, 설정 상태, 저장한 계획 목록은 초기화된다.

## 중간고사 새 기능의 인터랙션 시나리오 (26.10.23부 추가)

### 6. 완료한 계획 저장
- 사용자 행동: 완료 화면의 '완료한 계획 저장하기'를 누른다.
- 확인할 조건: 설정을 완료한 결과가 있는가? 같은 제목·준비 시간·질문 조건의 계획이 이미 저장되었는가?
- 성공 반응: 완료한 입력값의 복사본을 저장 목록에 추가하고 저장 개수와 성공 안내를 갱신한다.
- 다른 분기: 같은 계획이 있으면 추가하지 않고 '같은 계획이 이미 저장되어 있습니다'라고 안내한다. 질문 미포함일 때는 숨겨진 질문 수 차이를 중복 판정에서 제외한다.
- 다음 행동: '저장한 계획 목록 보기'를 눌러 목록으로 이동한다. 새 계획은 '다시 설정하기'로 작성한다.
- 상태 원칙: 다시 설정하면 현재 입력은 초기화하지만 이미 저장한 계획은 유지한다. 설정 완료 전에는 저장 버튼이 보이지 않으며, 저장 처리에서도 완료 여부를 검사한다.

### 7. 저장한 계획 다시 열기
- 사용자 행동: 저장한 여행 계획의 '다시 열기'를 누른다.
- 확인할 조건: 선택한 계획이 목록에 있는가?
- 성공 반응: 저장 당시의 여행 제목, 준비 시간, 질문 포함 여부와 질문 수를 상세 영역에 표시한다.
- 다른 분기: 목록이 비어 있으면 빈 목록 안내와 '여행 준비 설정으로 이동하기' 링크를 보여 준다.
- 다음 행동: '상세 닫고 목록으로 돌아가기'를 누르면 상세 영역을 닫고 해당 계획의 다시 열기 버튼으로 초점을 돌린다.
- 상태 원칙: 상세 보기는 저장한 결과를 확인하는 화면이다. 새로운 초안 입력이나 기존 저장값을 바꾸지 않는다.

### 8. 저장한 계획 삭제와 취소
- 사용자 행동: 계획의 '삭제' 버튼을 누른다.
- 확인할 조건: 삭제할 계획이 존재하는가? 확인창에서 실제 삭제를 선택했는가?
- 성공 반응: '삭제하기'를 누르면 선택한 계획만 제거하고 저장 개수를 갱신한다. 삭제한 계획의 상세가 열려 있으면 닫는다.
- 다른 분기: '취소하고 유지하기' 또는 Esc를 누르면 삭제하지 않고 취소 안내를 표시한다.
- 결과 없음: 마지막 계획을 삭제하면 빈 목록 안내와 새 계획을 만드는 경로를 보여 준다.
- 다음 행동: 남은 계획을 다시 열거나 여행 준비 설정으로 돌아가 새로운 계획을 만든다.
- 삭제 후 현재 완료 결과가 남아 있다면 완료 화면에서 다시 저장할 수 있다. 별도 삭제 복구 이력은 제공하지 않는다.

### 9. 9주차 추가·수정 사항 (26.10.29부 추가)
기존 여행 준비 다단계 입력을 하나의 form으로 묶고, 제목 검증·조건부 입력·제출 상태를 연결했다.
교안의 폼 UI 예제를 여행 준비 계획에 적용했으며 기존 테마·탭·저장 목록 기능과 디자인을 유지했다.
주석이 너무 많아 줄였다.
